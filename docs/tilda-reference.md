# Справочник по Tilda — что мы выяснили опытом

_Восстановлено 08.10.2026. Всё проверено на живом сайте 2young4u.ru,
а не взято из документации: доступа к справке Tilda из рабочей среды нет._

Каждый пункт здесь куплен потерянным временем. Читать до того, как лезть в код.

---

# 1. 🔑 ШАПКА И ПОДВАЛ «ВПЕКАЮТСЯ» В СТРАНИЦУ ПРИ ПУБЛИКАЦИИ

Tilda вкладывает в страницу **копию** шапки и подвала в момент публикации.
Дальше страница носит эту копию в себе. Правка подвала **не долетает** до
страниц, которые с тех пор не публиковались.

Один дефект дал три разных симптома одновременно:

| Страница | Состояние | Симптом |
|---|---|---|
| Главная | опубликована последней | всё работает |
| `/men/hoodies` | опубликована давно | попап открывается, но СТАРЫЙ |
| `/men/blazers` | не публиковалась после клонирования | 404 вместо попапа |

**Лечение:** «Ещё» → «Опубликовать все страницы».

⚠️ Она **пропускает** страницы без пометки «Последние изменения не
опубликованы». Такую надо сначала «пошевелить»: зайти в редактор, сдвинуть
блок вниз-вверх, чтобы пометка появилась, и только потом публиковать.

# 2. 🚨 КЭШ БРАУЗЕРА — ПРОВЕРЯТЬ ПЕРВЫМ ДЕЛОМ

После публикации браузер показывает старое. Симптом неотличим от поломки.

**Ctrl+U (исходный код) отдаётся ТОЖЕ ИЗ КЭША.** Приём «посмотрим, что реально
в коде» — обычно самый надёжный — в этой ситуации врёт. Мы построили на таком
коде три версии диагноза подряд, и все три оказались неверны.

> **При «правлю, а не меняется» → Ctrl+Shift+N (инкогнито), тридцать секунд.**

# 3. ПОПАПЫ ЖИВУТ ТОЛЬКО В ПОДВАЛЕ

Попап T1093 — всегда **пара**: движок с крючком + Zero-блок с содержимым:

```html
<div class="t1093">
  <div class="t-popup" data-tooltip-hook="#formanpopup"
       data-popup-rec-ids="rec2501315011">
```

**На обычных страницах блоков попапов быть не должно.** Признак дубля
в редакторе — розовая полоска «Линкхук: #...».

Дубль не даёт ошибки — он молча открывает **не ту** копию. Выглядит как
«ссылка не работает». Наступали трижды: главная, карточка товара, женский
попап, переживший первую уборку.

⚠️ При копировании блока Tilda даёт копии **новый `rec…` id**, и у движка надо
заново указать ID Zero-блока.

# 4. КОД ИЗ HEAD НЕ РАБОТАЕТ НА `/members/*`

На системных страницах кабинета HEAD не выполняется вообще.
**Решение:** класть такой код в блок **T123 на подвале** — подвал рендерится
везде, включая системные страницы.

# 5. СПЕЦИФИЧНОСТЬ: ПРАВИЛА TILDA СИЛЬНЕЕ ОДИНОЧНОГО КЛАССА

`!important` с одним классом проигрывает. Лечится повторением класса:

```css
/* 0,3,0 — побеждает внутренние правила Tilda */
.t780__price-wrapper.t780__price-wrapper.t780__price-wrapper {
  margin-top: 12px !important;
}

/* 0,4,0 — побеждает наше же правило выше */
.t2y-descr-moved.t2y-descr-moved.t2y-descr-moved.t2y-descr-moved {
  margin-top: 24px !important;
}
```

⚠️ **Медиазапрос специфичности НЕ добавляет.** При равной силе побеждает то,
что ниже по файлу — мобильное правило может проиграть десктопному,
стоящему дальше.

# 6. НЕСУЩЕСТВУЮЩИЕ КЛАССЫ МОЛЧАТ

`.t780__wrapper` на карточке **не существует**. Правила через него просто
ничего не делают — на этом дважды «не менялись отступы».

```css
/* диагностика: нет красной рамки — класса нет */
.подозрительный-класс { outline: 3px solid red !important; }
```

# 7. `position: fixed` НЕ РАСШИРЯЕТ ОБЛАСТЬ ПРОКРУТКИ

Элемент с `fixed` может торчать за край экрана — горизонтальной прокрутки это
не создаёт. Открепишь — торчащее начнёт растягивать страницу.

Поэтому карточка ехала вбок, а остальные страницы нет: у пунктов «Женское»
и «Мерч» в шапке нет мобильных координат, они стоят на 551px и 648px
при экране 360.

# 8. `static`, А НЕ `absolute` ПРИ ОТКРЕПЛЕНИИ

```css
/* ❌ выбрасывает из потока: содержимое остаётся ПОД шапкой */
position: absolute !important; top: 0 !important;

/* ✅ возвращает в поток: шапка раздвигает содержимое вниз */
position: static !important; top: auto !important;
```

На этом застряли надолго: я считал, что открепил, заказчик видел, что всё ещё
накрывает — и оба были правы.

# 9. `overflow: hidden` УБИВАЕТ `position: sticky`

ST210 держит колонку с ценой на `sticky`. Обрезать переполнение надо точечно:

```css
/* ✅ клипуем только ленту галереи */
html.t2y-card-page .t-slds { overflow: hidden !important; }

/* ❌ так нельзя — умрёт залипание цены */
#rec2463616301 { overflow: hidden !important; }
```

# 10. ВЁРСТКА КАРТОЧКИ — FLEX

Родитель названия товара — flex-контейнер. Вставленный блок становится вторым
**столбцом** и сжимается в полоску с переносом по буквам. `width: 100%`
не спасает. Решение — подняться до предка в обычном потоке:

```js
var anchor = title, parent = anchor.parentNode;
for (var i = 0; i < 3 && parent && parent.nodeType === 1; i++) {
  var d = window.getComputedStyle(parent).display;
  if (d !== 'flex' && d !== 'inline-flex' && d !== 'grid' && d !== 'inline-grid') break;
  anchor = parent; parent = anchor.parentNode;
}
parent.insertBefore(nav, anchor);
```

# 11. МОБИЛЬНОЕ МЕНЮ — БЛОК ME403 НА ПОДВАЛЕ

Не Zero-блок. Пункты правятся в Контент → «Список пунктов меню».
Ссылки — **относительные**: полные ломаются в предпросмотре.

Диапазон видимости расширен с 0–480px до **0–640px**: широкие телефоны отдают
480px+, и у них меню не появлялось.

# 12. ПОЛЯ TILDA НЕ ПРИНИМАЮТ HTML

«ТЕКСТ ПОД ФОРМОЙ» в корзине выводит теги как обычный текст.
Ссылки добавляются только скриптом — `footer/cart-legal-links.html`.

# 13. ЭЛЕМЕНТЫ ШАПКИ ИСКАТЬ ПО СТАБИЛЬНОМУ `src`

`id` и `data-elem-id` меняются при публикации. Иконки ищем по куску адреса:

```js
var BAG_SEL = 'img[src*="tild6131-6365-4831-a632-303931386531"]';
```

Номера `rec…` при этом **стабильны**, на них опираться можно.

# 14. У ST210 НЕТ ХЛЕБНЫХ КРОШЕК

У ST340 (страницы категорий) есть и работают. У ST210 (карточка) — нет.
Поэтому на карточках свой скрипт, а категорию он берёт из data-атрибутов
блока `.t2y-acc-source` на странице товара.

# 15. ХАРАКТЕРИСТИКИ НЕ ВЫВОДЯТСЯ НА ST210 АВТОМАТИЧЕСКИ

Заполненные в каталоге характеристики на карточке не появляются.
Поэтому аккордеоны собираются вручную из блока текстов на странице.

# 16. ФОРМАТ CSV КАТАЛОГА

## Один товар = несколько строк

Родитель плюс по строке на размер.

| Поле | Родитель | Вариант |
|---|---|---|
| Название, описание, фото | ✅ | дублируется |
| Category, характеристики | ✅ | пусто |
| **Price, Quantity, SKU** | ❌ **ПУСТО** | ✅ |
| Editions | ❌ **ПУСТО** | `Размер:M;Цвет:Синий #073763` |
| Parent UID | пусто | **External ID родителя** |

⚠️ **Цена и остаток живут у размеров, а не у товара.**

## Три грабли, на которые наступили

**1. `Empty Uniq column: uid`** — в файл попала колонка `Tilda UID` из экспорта.
У новых товаров она пустая, а Tilda считает её ключом уникальности и отвергает
каждую строку. **В импорте этой колонки быть не должно.**

**2. Варианты не привязались** — у родителя был заполнен `Editions` строкой
`product_options:[…]` из экспорта. Это представление на ВЫГРУЗКУ. При импорте
набор опций Tilda собирает сама из строк-вариантов. **У родителя пусто.**

**3. 🎯 Главная.** Внизу экрана сопоставления — «Группировка вариантов товара».
Он **сбрасывается между загрузками** на «Группировать по SKU».

> **Должно стоять «Группировать по Parent UID». Проверять КАЖДЫЙ раз.**

Из-за него пять импортов подряд дали разные и одинаково неверные результаты:
при «по SKU» наши размеры (одинаковый артикул) слипались в один товар,
а варианты из шаблона Tilda (у каждого свой артикул) разлетались по отдельным.

## Разделы

```
"Мужское;Мужское>>>Костюмы;Капсулы;Капсулы>>>Ватаным"
```

Несколько через `;`, вложенность через `>>>`, ячейка **в кавычках**.
Родитель указывается **отдельно** от подраздела: **Tilda разделы НЕ наследует.**

## Фото

✅ **`.webp` ПРИНИМАЕТСЯ (проверено 08.10.2026).** Ссылки из фида VipAvenue
ведут на `media2.vipavenue.ru/.../*.webp` — Tilda скачивает их к себе без
вопросов. Это снимает ручную заливку фотографий для всего каталога.

Ссылки **через пробел**. Можно подставлять внешние прямые ссылки —
Tilda скачает к себе. Нужна ссылка непосредственно на файл, а не на страницу
просмотра: ссылки Яндекс.Диска вида `disk.yandex.ru/d/…` не работают.

## Формат экспорта ≠ формат импорта

Экспорт отдаёт больше колонок. **Сверяться надо с `import_example.csv`**
(ссылка «пример CSV файла» в окне импорта), а не с выгрузкой.

# 17. ПОРЯДОК ДИАГНОСТИКИ «ПРАВЛЮ, А НЕ МЕНЯЕТСЯ»

Строго по порядку, не перескакивая:

1. **Инкогнито.** Треть случаев закрывается здесь.
2. **Пометка «Последние изменения не опубликованы»** в списке страниц.
3. **«Опубликовать все страницы»**, при нужде «пошевелив» страницу.
4. **Розовые полоски «Линкхук»** на странице — дубль попапа.
5. Только теперь — смотреть код и менять его.

**Инструменты:**

| Файл | Что делает |
|---|---|
| `head/DIAGNOSTIC-overflow-finder.html` | список «что торчит за экран, в каком блоке, насколько» |
| `head/DIAGNOSTIC-site-audit.js` | обход всех страниц из консоли: попапы, подвал, битые ссылки |
| `outline: 3px solid red` | жив ли класс |

> **Вывод, оплаченный временем: дороже всего обходятся случаи, когда меняешь
> код, не увидев настроек.**
