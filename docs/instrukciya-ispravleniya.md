# ЭТАП 1. Четыре правки по минуте каждая

Безопасные, ничего не ломают. После всех четырёх — **Сохранить изменения**
и **опубликовать все страницы**, потом проверить сайт в инкогнито.

## 1.1 Очистить битую ссылку на шрифт ✅

**Настройки сайта → Шрифты → вкладка Google Fonts → поле CSS LINK**

Там стоит `https://fonts.google.com/specimen/EB+Garamond?query=garamond`.
Это адрес страницы-витрины, а не файла стилей. Браузер скачивает 63 КБ
HTML, пытается прочитать как CSS, выбрасывает — и всё это время
**не рисует страницу**.

**Стереть поле целиком.** Поля «Шрифт для заголовков» (Tenor) и «Шрифт
для текста» (Raleway) не трогать.

⚠️ После публикации глянь главную и карточку товара. Raleway подключён
отдельной правильной ссылкой, Tenor Sans идёт из библиотеки Tilda —
пострадать не должны. Но если где-то в Zero Block кто-то вручную выбрал
Garamond, там шрифт сменится на запасной. Тогда вернёшь ссылку,
но правильную: `https://fonts.googleapis.com/css2?family=EB+Garamond:wght@400;600`

## 1.2 Очистить поле Google Tag Manager ✅

**Настройки сайта → Аналитика → GOOGLE TAG MANAGER ID**

Там `UA-147736966-1`. Контейнер GTM имеет вид `GTM-XXXXXXX`. Сейчас
на каждой странице грузится 136 КБ скриптов, которые шлют данные
в Universal Analytics — систему, отключённую Google в 2023 году.

**Стереть поле.** Если позже понадобится GTM — заведёте контейнер
и впишете правильный `GTM-`.

## 1.3 Включить показ системного шрифта при загрузке ✅

**Настройки сайта → Шрифты → внизу «Продвинутые настройки»**
→ галочка **«Показывать системный шрифт при загрузке»**

Сейчас, пока грузится шрифт, текст не виден вообще. С галочкой текст
появляется сразу системным шрифтом и подменяется, когда доедет нужный.

## 1.4 Включить защиту от подмены контента ✅

**Настройки сайта → Ограничить доступ → Дополнительные серверные заголовки**
→ **«Включить защиту от подмены контента»**

Проверил: сервер не отдаёт `x-content-type-options: nosniff`. Включение
безопасно и ничего не ломает.

⛔ **«Включить защиту от XSS атак» НЕ трогать.** Tilda прямо под галкой
пишет, что Google, Facebook и GitHub от этого заголовка отказались.

⛔ **«Отключить защиту от фреймов» НЕ трогать.** Проверил: защита сейчас
работает (`x-frame-options: SAMEORIGIN`), и это правильно.

# ЭТАП 2. Аналитика — чтобы не запускаться вслепую

Сейчас работает только встроенная статистика Tilda. ✅ Проверено:
в коде сайта нет ни Метрики, ни рабочего Google Analytics.

## 2.1 Яндекс.Метрика — ставить первой

Для российского магазина она полезнее GA4: бесплатный вебвизор (запись
действий покупателя), карта кликов, отчёты по электронной торговле.

1. `metrika.yandex.ru` → **Добавить счётчик**
2. Имя — «2young4u», адрес сайта — `2young4u.ru`
3. Включить **Вебвизор, карта скроллинга, аналитика форм**
4. Включить **Электронная коммерция** — тогда будут видны заказы, корзины
   и брошенные корзины
5. Создать → скопировать **номер счётчика** (8 цифр)
6. В Tilda: **Настройки сайта → Аналитика → ЯНДЕКС.МЕТРИКА** → вставить номер
7. Сохранить → опубликовать все страницы
8. Через час зайти в Метрику и убедиться, что визиты идут

## 2.2 Google Analytics 4

Старый `UA-147736966-1` не воскресает — нужен новый ресурс.

1. `analytics.google.com` → **Администратор** → **Создать ресурс**
2. Название «2young4u», часовой пояс и валюта — Россия / RUB
3. Создать **поток данных** типа «Веб», адрес `2young4u.ru`
4. Скопировать **идентификатор потока** вида `G-XXXXXXXXXX`
5. В Tilda: **Настройки сайта → Аналитика → GOOGLE ANALYTICS** —
   стереть старый UA и вставить `G-…`
6. Сохранить → опубликовать

❓ Если поле не примет значение на `G-` — значит у проекта старая версия
настроек. Тогда вставить код GA4 вручную в **Настройки сайта → HTML-код
внутрь HEAD**, и скажи мне, я соберу готовый кусок.

## 2.3 Search Console и Яндекс.Вебмастер

Нужны **перед открытием индексации**: туда отправляют карту сайта,
оттуда видно, какие страницы проиндексировались и где ошибки.
Делается через **Настройки сайта → SEO** — там готовые кнопки
«Google Search Console» и «Яндекс Вебмастер».

# ЭТАП 3. То, без чего нельзя продавать

## 3.1 Проверить почтовые уведомления о заказе ❓

**Настройки сайта → Платёжные системы → внизу «ОБЩИЕ НАСТРОЙКИ» → Настроить**

Два пункта:
- **Почтовые уведомления об успешном заказе** — включить обязательно.
  Без них человек оплатит и не получит подтверждения
- **Проверка цены товара и доставки перед переходом к оплате** — тоже
  включить: защищает от ситуации, когда корзина провисела полдня,
  а цена изменилась

Снаружи их состояние не видно — посмотри и скажи, что там стояло.

## 3.2 Создать `/offer` и `/privacy` ✅

Страниц нет (404), и в корзине слова «публичная оферта» и «согласие
на обработку персональных данных» — просто покрашенный текст без ссылки.
То есть покупатель физически не может их прочитать.

1. Спросить у заказчицы **реквизиты**: юридический статус (ИП / ООО /
   самозанятый), полное наименование, ИНН, ОГРН/ОГРНИП, юридический адрес,
   контактный телефон и почта
2. Взять черновики `docs/draft-offer.md` и `docs/draft-privacy.md`,
   подставить реквизиты вместо `[…]`
3. Создать две страницы с адресами `/offer` и `/privacy`
4. В корзине сделать слова ссылками — цветом ты уже их выделил,
   осталось повесить ссылки

⚠️ Черновики писал я, не юрист. Перед запуском их стоит показать юристу —
в файлах есть таблица спорных мест.

## 3.3 Создать `/returns` ✅

Ссылка «Возврат» стоит в подвале **на всех 38 страницах** и ведёт в 404.
Либо сделать страницу, либо убрать ссылку. По закону условия возврата
покупатель должен видеть до оплаты, так что лучше сделать.

## 3.4 Сделать страницу 404 👁

Сейчас в настройках «СТРАНИЦА ОШИБКИ 404: Не выбрано», и человек видит
голую страницу Tilda — без шапки, логотипа и меню. Тупик.

1. Создать страницу: логотип, «Страница не найдена», кнопка «В каталог»
2. **Настройки сайта → Ещё → СТРАНИЦА ОШИБКИ 404** → выбрать её
3. Опубликовать

Нужна в любом случае: люди приходят по старым ссылкам из поиска
и мессенджеров.

## 3.5 Решить судьбу «Комплектов» ✅

`/men/sets` отдаёт 404, а `/women/sets` открывается. Заказчица просила
убрать раздел из обоих. Либо убрать ссылку из меню и женскую страницу,
либо вернуть мужскую.

## 3.6 Разобраться с AmoCRM 👁

В разделе «Формы» интеграция **«AmoCRM: Приобрели с сайта» заблокирована**.
Заказы туда не уходят. Если AmoCRM используется — переподключить,
если нет — удалить, чтобы не висела.

# ЭТАП 4. Настоящий тестовый заказ

✅ Проверено: в CRM все тестовые заказы со статусом **«Не оплачен»**.
Значит цепочка корзина → банк → возврат на сайт → письмо → «Оплачен»
**не проходилась ни разу**.

Полный список проверок — в `docs/proverka-puti-pokupatelya.md`.
Коротко, главное:

1. Инкогнито, **с телефона** (там 95% покупателей)
2. Товар → размер → корзина → оформление → оплата
3. Оплатить **по-настоящему**, на минимальную сумму. Тестового режима
   у Тинькофф может не быть — тогда потом вернёшь
4. Проверить: вернуло ли на страницу «спасибо»
5. Проверить **письмо покупателю** — и в папке «Спам» тоже
6. Проверить **уведомление магазину** на `2young4U.sales@gmail.com`
7. Проверить в CRM: статус стал **«Оплачен»**, сумма верная
8. Отдельно: **отменить оплату** на странице банка и убедиться,
   что корзина осталась цела

# ЭТАП 5. Перед открытием индексации

## 5.1 Мета-описания ✅ (0 из 46 страниц)

«Описание сайта» в общих настройках до страниц **не доезжает** — оно
только для списка проектов. Заполняется на каждой странице:
**Настройки страницы → SEO → Описание**, 120–160 символов.

Приоритет: главная → `/men`, `/women` → разделы каталога → карточки.

## 5.2 Заголовки H1 ✅ (0 из 46 страниц)

Во всём коде сайта один `<h3>` и ни одного `<h1>`. Поисковику нужен
сигнал «о чём страница».

В Zero Block: выделить текстовый элемент с названием → в настройках
элемента выбрать тег **H1**. Сделать для названия товара на карточке
и названия раздела в каталоге. **По одному H1 на страницу.**

## 5.3 Атрибуты alt ✅ (0 из 468 картинок)

В настройках картинки есть поле **ALT** — короткое описание того,
что на фото: «Олимпийка хлопковая синяя, вид спереди».
Начать с главной и карточек.

## 5.4 Вернуть индексацию 🔴

**Настройки сайта → SEO → снять «Запретить поисковикам индексировать»**

Делать **последним**, когда всё выше готово. Закрыта 13.09.2026.

После этого проверить `sitemap.xml` — сейчас он пустой (0 байт).
Возможно, он пустой именно из-за запрета и наполнится сам. Если нет —
скажи, разберёмся.

# ЭТАП 6. Уборка, когда дойдут руки

- **Видео на главной** — 4,73 МБ, выключить на разрешениях 320 и 480,
  вместо него стоп-кадр. Самое тяжёлое, что осталось на сайте
- **Четыре товара с невидимым названием `ㅤ`** — открыть по uid
  (адреса в `docs/audit-polnyy-obhod-15-10-2026.md`), дать название
  или удалить
- **Страница `/shop`** — дублирует `/men/hoodies`, ни с чего не ссылается
- **`/men ` и `/women ` с пробелом** в ссылках шапки — на всех 46 страницах
- **Дубль блока поиска** на карточках (`rec4680828001`)
- **Модуль «Курсы»** — магазину одежды не нужен
- **Пять тяжёлых JPEG** — пережать, минус ~800 КБ
